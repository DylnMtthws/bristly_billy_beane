# Security policy

Report vulnerabilities privately to the repository owner through GitHub's
private vulnerability reporting feature. Do not publish exploit details,
credentials, account information, or production data in an issue or PR.

Only the default branch is maintained. Security fixes are reviewed with tests
that reproduce the issue using synthetic data. No response-time SLA is promised.

Local development settings are not public-hosting defaults. Keep session secrets
and provider keys outside Git, use HTTPS, and validate authorization on the server.

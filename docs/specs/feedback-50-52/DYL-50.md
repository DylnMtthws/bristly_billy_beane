# DYL-50 — Responsive builder card autocomplete
Report: card search takes too long in the deck builder.
Investigate the full /api/cards path. Current search runs nested punctuation replacements across card names, then a correlated printing choice/order; route loads a full deck document plus tags/playmats merely to derive commander identity. Measure the actual causes, preserve substring and punctuation-tolerant matching, exact/prefix relevance, unique results, limit=8, and authorization.
Implement a bounded performant local solution. Prefer reusable indexed normalization or a bounded catalog cache with explicit data-version invalidation over repeated scans/sorts. Do not preload private deck documents into global caches. If schema/index added, use idempotent additive migration and test existing populated DB upgrade, and ensure new/updated cards are searchable. No dependency installation or external network search.
Keep 180ms or shorter typing debounce, abort stale fetches, Escape dismissal and keyboard selection; never allow old responses or old commander scope to reappear. Avoid full deck hydration per keystroke. No new delay animations.
Acceptance: focused API tests verify authorization, unique/ordered results, punctuation and substring, capped result size and updated catalog/commander changes. Include a reproducible >=30k-card benchmark with cold and repeat timings and query-plan evidence; target local server search under 150ms warm and under 400ms cold for common terms. Coordinator measures actual QA latency and verifies UI keyboard and stale response behavior.
